# 重复影像转场首页设计

## 目标

将当前 `/` 的球幕“每日推荐”首页替换为一个摄影作品推荐网格，并参考 Codrops 的 [Repeating Image Transition](https://github.com/codrops/RepeatingImageTransition/) 实现卡片到详情页的重复影像转场。现有 `/gallery` 画廊、3D/Flat 切换、拖拽和悬停交互保持不变。

新首页不是 Codrops 示例的逐像素复刻。它沿用项目已有的纯白底色、克制的黑灰文字、摄影作品数据和顶部导航，让首页与画廊看起来属于同一个产品。

## 用户体验

### 默认状态

- 页面背景为纯白色，不恢复日夜模式。
- 顶部保留小尺寸的“推荐 / 画廊”导航，其中“推荐”为当前页面。
- 内容顶部采用参考页面的编辑式信息排版：一行四段简短资料、左侧大标题和右侧操作提示。文案只描述本页真实内容，不使用示例站的广告或模板文案。
- 主体展示 12 张精选摄影作品：桌面端 4 列，窄屏端 2 列。
- 卡片只展示作品图、摄影师、分类和年份，不出现模板营销文案。
- 卡片外观沿用画廊的排版语言：轻量、留白充足、黑灰文本，不添加厚重边框或装饰画框。
- 鼠标悬停时仅降低图片透明度并增强文字对比度，不添加灰色背景或黑色边框。

### 打开作品

1. 用户点击卡片。
2. 未选卡片根据与选中卡片的距离依次淡出并轻微缩小。
3. 页面根据源缩略图和目标大图的实际矩形位置生成 6 个线性插值的中间位置，并在每个位置创建一个静止影像副本。
4. 六个副本按 50ms 间隔依次通过 `clip-path` 从底部裁切状态显现、停留 140ms，再向底部裁切退出，形成与参考源码一致的视觉路径。
5. 详情面板完成显现，临时节点被清理。

选中左半屏卡片时，大图落在详情右侧；选中右半屏卡片时，大图落在详情左侧。这样转场方向与用户点击位置一致，也避免文字层和路径重叠。

### 详情状态

- 详情面板占满视口，由大图和精简信息区组成。
- 信息区只展示摄影师、作品序号、分类和年份。
- 提供明确的“返回”按钮；按 `Escape` 也可关闭。
- 关闭时采用简短淡出，再恢复网格，不播放冗长的完整反向轨迹。
- 详情打开期间隐藏顶部导航，避免层级冲突。

### 响应式与可访问性

- 桌面端详情采用左右分栏，移动端改为上下布局。
- 移动端仍根据卡片所处区域选择视觉方向，但轨迹长度和副本间隔缩短。
- 卡片使用原生按钮或具备等价键盘语义的元素，支持键盘打开。
- 详情打开时阻止背景滚动；关闭后恢复焦点到原卡片。
- 对 `prefers-reduced-motion: reduce` 用户，禁用重复副本轨迹，改用源卡片和详情面板的直接交叉淡入淡出。

## 技术方案

### 组件边界

- `app/page.tsx`：首页路由入口，只负责组合推荐首页与导航。
- `app/featured-home.tsx`：客户端状态和交互协调，包括当前作品、转场阶段、焦点恢复及背景滚动锁定。
- `app/featured-card.tsx`：单张作品卡片，负责展示和向父组件报告点击来源元素。
- `app/featured-detail.tsx`：全屏详情布局和关闭入口。
- `lib/repeating-transition.ts`：无框架的几何与时间参数计算，生成可测试的副本轨迹描述。
- `lib/featured.ts`：从现有作品数据中选出首页使用的 12 张作品，并转换为首页所需字段。

实际实现时可以在保持上述职责边界的前提下合并非常短小的展示组件，避免为少量标记创建无价值文件。

### 动画实现

使用与参考源码一致的 `gsap@3.12.7` 时间线。选择 GSAP 是为了保持 `sine`、`sine.in`、`sine.inOut` 和 `expo` 缓动、相对时间位置、延迟与完成回调的行为一致，而不是用 Web Animations API 近似模拟。

转场模块接收源矩形、目标矩形和配置，输出 6 个不含源与目标端点的中间矩形。默认参数：

- 副本数量：6
- 单步持续时间：350ms
- 副本间隔：50ms
- 详情显现停顿：140ms
- 路径：中心点与宽高的线性插值，中间副本位置固定
- 旋转和随机抖动：关闭

网格退出、面板图片揭示、面板文案揭示、关闭还原均按参考源码的默认时长与缓动执行，不做主观微调。所有临时副本使用 `position: fixed` 和 `pointer-events: none`，动画完成或组件卸载时必须取消时间线并移除节点。

### 状态流

首页只有四个显式阶段：`idle`、`leaving-grid`、`revealing-detail`、`detail`。转场期间忽略重复点击，防止创建重叠副本。关闭详情后回到 `idle`。

图片沿用 `public/art` 中已有本地资源，不引入远程图片请求。图片加载失败时保留卡片信息和中性占位背景；动画仍可完成，不让页面卡在中间状态。

## 删除与保留范围

### 删除

- 当前球幕首页组件 `app/daily-scene.tsx`。
- 当前球幕首页专用数据与测试 `lib/daily.ts`、`lib/daily.test.ts`。
- 首页椅子模型 `public/models/bertoia.glb` 及其专用授权说明，因为新首页不再使用 3D 椅子。
- 与旧首页球幕、椅子和底部署名相关且不再被引用的样式。

### 保留

- `/gallery` 页面及其交互逻辑。
- 画廊使用的 Three.js 依赖和全部投影、交互、主题测试。
- 现有 16 张本地作品资源和作品数据。
- 顶部“推荐 / 画廊”导航，只将首页标签从“每日推荐”精简为“推荐”。

删除内容均受 Git 版本控制，可从历史恢复。实现不得顺手调整画廊视觉或重构画廊内部结构。

## 测试与验收

### 自动测试

- 轨迹生成返回固定数量的副本，并严格包含源、目标端点。
- 左右落位逻辑在视口中线两侧得到相反结果。
- 延迟按副本索引递增，动画总时长可确定。
- 精选数据固定为 12 项，字段完整且资源路径来自现有作品。
- 保留并通过现有画廊投影、交互和主题测试。
- 运行 TypeScript 类型检查、Oxlint、Node 测试和生产构建。

### 浏览器验收

- 桌面端网格为 4 列，移动端为 2 列，没有水平溢出。
- 左右两侧卡片打开时，详情图片分别落在相反侧。
- 快速连点不会产生残留副本或多个详情面板。
- “返回”和 `Escape` 均可关闭详情并恢复焦点。
- 减少动态效果模式下没有重复影像轨迹。
- 直接访问 `/gallery` 时，已有画廊布局、3D/Flat 切换、拖拽和悬停效果不变。
